what it does

asd sits between a search call and a fetch call. When a search runs, all ten results are checked into a cache instead of being discarded at the end of the turn. When a page is loaded, asd stamps it into an ordered visit log and serves it from cache if it's already there — full content, not just the snippet, once fetched once.

visit_log

how it runs

On each search query

  1. Run a search, get up to ten results.
  2. Check each new url into result_cache — duplicates by url are skipped.
  3. Return the ten results to the caller as usual.

On each load trigger

  1. Increment that url's visit count; append it to visit_log.
  2. Fetch full content if it isn't cached yet — otherwise serve the cached copy.
  3. Return the page content plus its position in visit_log.
house rules
  • A cached url is never re-searched — served from cache unless a refresh is explicitly requested.
  • Cache entries expire after a caller-set window; expired entries are re-fetched on next visit, never dropped from visit_log.
  • visit_log is the record of order — "which page came third" is a visit-log question, not a search-rank question.
  • result_cache is the record of content.

# asd

A search-result circulation agent.

## State (persisted across calls)
- result_cache: list of {url, title, snippet, query, fetched_at, visit_count}
- visit_log: ordered list of urls, appended each time a page is loaded

## On each search query
1. Run web_search, get up to 10 results.
2. Check each new result into result_cache (dedup by url).
3. Return the fresh 10 results to the caller as usual.

## On each "load" trigger
1. Increment visit_count for the requested url; append url to visit_log.
2. Fetch full content if not cached, or serve from result_cache.
3. Return that page's content plus its position in visit_log.
